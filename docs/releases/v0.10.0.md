# Dkord v0.10.0 — online Studio, explicit downloads and co-host rooms

## Android: new in this release
- **Mashup Studio accepts ordinary online songs directly.** Search/select a catalogue song inside Studio or open it from a song action, without manually adding it to Downloads first. Accessible audio is fetched to private staging, probed and retained as a durable editable source. Existing phone/offline imports, precise clips, ordering, preview and real AAC/M4A export/share remain.
- Every player/song/bulk download action offers **Download in Dkord** (private offline library) and **Download to device** (an accessible independent Music/Dkord or selected-folder copy). Existing complete audio is reused, including offline local-copy work. A device-copy failure is not reported as private-fallback success. Private saves still consume device storage; independent device copies remain when an app-private download is removed.
- **Listen Together co-hosts:** creator-only by default; allow one, two or more selected updated members, or Everyone including new members. Permitted in-app play/pause/song/queue/seek actions reach listeners who opted into Sync/Follow. The creator alone administers access and can revoke individuals or reclaim all controls. Grant/revoke never starts audio or enables Follow by itself.
- Room proposals/policies and canonical playback use bounded room-bound signatures, sequence/revision/session checks and ephemeral member IDs, with EN/HI permission UI. Retry retains consent/identity; Leave/new room discards pending room intents and expires deferred remote player callbacks without stopping normal local playback. Buffering/progress/remote sync cannot echo guest commands.
- Existing one-way rooms/listeners remain supported. Co-host controls require updated participating clients; guest headset/notification controls remain local in this version. The creator must stay reachable. Public ntfy metadata is **not end-to-end encrypted or verified-account/private-server membership**; share codes only with trusted people. See [room controls](https://github.com/DeepuExplainsAi/dkord/blob/v0.10.0/docs/ROOM_CONTROLS.md).
- Preserve existing playback, anonymous related radio, Listen Again/history, likes/playlists, local files, search/real keyboard behavior, English/Hindi interface, Choliwood naming, optional video, lyrics and in-app Android update flow. No account/cookie sign-in, destructive reset or replacement theme/signing key is introduced.

## Install/update Android without losing existing data
Download **Dkord-v0.10.0.apk**, or accept the in-app update. **Install over your existing Dkord installation; do not uninstall or clear app data.** Package stays `app.dkord`; versionCode **14** increases from v0.9.1/code13. Publication verifies the actual old/new APK signing certificates, package and increasing version. Downloads database migration is additive; old paths/URIs, settings, library and Studio files are not moved or reset merely by upgrading.

Android 8/API26+ is supported. Android26–28 asks for a real document-provider folder for device copies. Provider/region/account/network restrictions, document-provider permissions, codec and free-space limits still apply. Online editing must fetch audio bytes and cannot edit inaccessible/DRM audio by pretending it is available.

## Windows, macOS and Linux — experimental desktop previews
Separate native **Windows x64 exe**, **Intel Mac / Apple Silicon pkg**, and **Linux x64 / arm64 deb + AppImage** assets are included. They provide a PC-adapted Qt player/library, explicit private/device storage, online/device/offline Studio and native packaging. Linux builds conservatively require **glibc2.39 / Ubuntu24.04-class or newer**, plus the listed native audio/GUI libraries. macOS13+ is the current minimum.

**These desktop files are development previews, NOT trusted signed/notarized production updates and NOT finished Android feature parity.** macOS uses ad-hoc preview signing; Windows has no Authenticode; do not disable OS security to treat them as trusted. Listen Together interoperability, enhanced recommendation parity, optional video, timed lyrics, full EN/HI controls and OS media integration remain open. Desktop production update trust keys/channel are intentionally unconfigured, so untrusted updates are refused. No automatic phone-to-PC/audio cloud sync is provided; JSON transfers metadata, not audio. User data is outside executable installation directories; physical install-over/data-retention acceptance is still pending.

## Executed validation and honest limits
Publication requires successful **full Android validation at this exact release head**: **432 JVM cases +38 Android35 emulator cases**, all10 mandatory classes, APK compilation and no failed/error/skipped device cases. The signed pipeline also reruns the full JVM suite and verifies real old/new APK compatibility. Desktop previews must come from successful same-head five-host native CI: **30 cases/all3 classes on each host**, actual Qt entry/frozen/package/AppImage smoke, package digests and source provenance verified before uploading. SHA256SUMS includes the APK and desktop previews; hashes are integrity evidence, not OS trust signatures.

These are executed automated checks, **not** a completed physical-phone/OEM update-over test, live multi-phone ntfy/music-provider acceptance, trusted native signing/notarization or a claim that all desktop parity gaps are finished. The [acceptance checklist](https://github.com/DeepuExplainsAi/dkord/blob/v0.10.0/docs/PLATFORM_ACCEPTANCE.md) remains explicit. Related music is best-effort metadata/context matching, **not account-personalized YouTube Music AI** or acoustic mood recognition. Old releases/tags/assets are preserved. Publication does not merge PR #8 or main.
