The requested gallery captures **30 production pages/dialogs/theme states on each

`65f1d728d9ad1a4f76085e5bceebff8317033ff3` earned

reviewed, plus full-size link/Hindi/player/Studio originals. This is actual
preparation evidence, **not a published0.10.2 release**.

Visual review caught a real readability defect in the pre-existing native player:
Windows32/Qt5 and macOS native tab chrome drew white backgrounds under inherited
white Artwork/Lyrics/Queue labels. A scoped phone-palette correction and rendered
pixel regression now cover every tab/selection in dark/light/AMOLED themes. That
final visual correction must earn fresh native tests and a recaptured gallery
before publication. Old v0.10.1 pictures are never reused as new-feature proof.

Targets: Windows x64 and genuine x86/32-bit; macOS Intel and Apple Silicon;
Linux x64 and arm64. Screens are generated by the actual installed-runtime
application's opt-in `--capture-gallery` QA command using `QWidget.grab`, not a
phone, web-app mockup, AI image, composite or retouched reconstruction. Linux
uses an isolated X display; Windows/macOS use their native Qt platform plugins.
This is virtual-host execution, not physical hardware acceptance.

## Honest sample data and safety

**OFFLINE DEMO:** audio consists of real locally generated sine-tone WAV files;
search/link metadata is an explicitly labelled fixture, not claimed live YouTube
metadata. Preview screenshots do not establish real stream availability or heard
audio. No room is started, no real query is sent, no download is enqueued by a
chooser, no user library is read/reset and no original audio file is used.

Each platform's `gallery-proof.json` records the exact source, version, actual
OS/CPU bitness/Qt/frozen status, screen identity/dimensions and original PNG
SHA-256. Release staging must verify all180 images and all six runtime receipts
before packaging the offline `index.html` gallery and originals into
`Dkord-PC-screenshots-v0.10.2.zip`. A corresponding public JSON manifest and the
common release checksums bind those bytes. Images and native installers remain
CI/release artifacts, not committed bulk binaries.

Normal application launch never activates screenshot fixtures. A screenshot
output must be new/empty; existing directories/files/captures are never replaced.
The legacy two Windows32 captures and their immutable historical receipts remain
separate and unchanged.
